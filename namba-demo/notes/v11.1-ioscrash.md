# v11.1 — iOS crash after loading (iOS-crash agent notes)

Status: DONE in emulation. Root cause found and fixed. Zack needs to retest on the iPhone: emulation can't reproduce
jetsam.

## Symptom

Zack's iPhone (iOS 18.7, 852×393 landscape, quality `low`, touch): `$pageview` → `namba_start` → tutorial `look` and
`move` at t ≈ 12 s → nothing. No `namba_perf` at 45 s, no `$pageleave`. The page died without unloading, which is how
iOS jetsam kills a WebContent process that is over its memory limit.

## Root cause (measured): world canvases at desktop size

`tools/memprobe.mjs` hooks every canvas and every WebGL texture, buffer and renderbuffer upload, then follows the
real timeline: load → Begin → 30 s of stick + look → phone → Maps → Lodestone → a world tour. It runs in iPhone
emulation (852×393, DPR 3, isMobile, hasTouch) on the shipped mobile tier.

**Before**, already at the title screen: **256 MB of 2D canvases + 319 MB of GPU textures**. Every sign, menu,
poster, departure board and shop atlas was a 2048² (or 2048×768, 1024×4096…) canvas: 67 canvases. Each was then
uploaded again as a mip-mapped GPU texture, so it existed twice. The biggest consumers, at 30 s of play:

| Consumer | 2D canvas | GPU texture |
|---|---|---|
| Shop dressing atlases (`world/env/atlas.js`, 2048² pages; 7 at Begin, 12 after a tour) | 112 MB | 171 MB |
| Wayfinding signage atlas (`world/signage.js`, 3 × 2048²) | 48 MB | (in the above) |
| Departure boards (`transit/boards.js`, 17 × 2048×768) | 27 MB | 8 MB+ |
| Transit emissive atlas 1024×4096, fare charts 2×2048×640 | 26 MB | 28 MB |
| Outdoor shop/sign/foliage atlases (2048×1024, 1920×960) | 23 MB | 31 MB |

The rest of the footprint: JS heap 69 MB, ArrayBuffers 274 MB (geometry CPU copies 118 MB, DataTexture data 47 MB,
packed lighting atlas 33 MB, nav 17 MB, lighting levels 19 MB), GPU vertex buffers 55 MB.

Total at 30 s of play: about **1.0 GB**, and still growing as lazy atlas pages fill (tour: 348 MB of 2D + 447 MB of
textures). iOS Safari also caps total canvas memory at about a quarter of the process limit (the "Total canvas
memory use exceeds the maximum limit" family). We were at 272 MB of 2D canvas before the phone opened.

**Hypotheses checked and ruled out (with numbers):**

| Hypothesis | Measured | Verdict |
|---|---|---|
| Map bakes (Maps + Lodestone, `maprender`/`ldmap`) | +4 MB (Maps) and +7 MB (Lodestone, both bakes + its canvases); ppm is already 3 on `low` | minor |
| Second WebGL context (stack3d) | 2.4 MB drawing buffer + 1.1 MB textures | minor (kept; see Risks) |
| Background shader precompile right after Begin (`precompileRest`) | compiling every chunk adds **6** programs (53 → 59) | not it |
| Crowd flow fields | N = 110 k nodes, 220 KB per field: 6–13 MB in total | not it |
| Skinned near agents | `low` already caps near LOD at 8 | not it |

## Fixes

| File | Change |
|---|---|
| `js/render/canvasres.js` (new) | `lcanvas(w, h, kind)`: a canvas whose **drawing space** stays w × h logical px (the context starts with a scale transform), backed by `w·s × h·s` real pixels. Producers keep their coordinates, fonts and UVs. `setCanvasRes({atlas, sign, board})`. On desktop every scale is 1, so the result is byte-identical to before. |
| `js/world/env/atlas.js` | Pages use `lcanvas(…, 'atlas')`. The edge-bleed `drawImage(self)` source rects are converted to real px (`c.ls`). |
| `js/world/signage.js` | Atlas pages use `lcanvas(…, 'sign')`. UVs use the logical size (`canvas.lw`). |
| `js/world/transit/textures.js` | `canvas()` (boards, emissive atlas, fare charts, machine faces) → `lcanvas(…, 'board')` |
| `js/world/outdoor/storefront.js`, `outdoor/textures.js` | Shop/sign atlases and the foliage atlas use `lcanvas(…, 'atlas')` (not the `putImageData` strata texture) |
| `js/main.js` | Touch devices: `setCanvasRes({ atlas: 0.5, sign: 0.6, board: 0.5 })` (`?fullres` turns it off for A/B). Crash recovery: `readRecovery()` before the tiers; if the last run died, a **safe tier** (see below). `armRecovery(ctx, rec)` right after ctx. |
| `js/render/lighting.js` | Mobile only: the packed half-float lighting atlas (CPU copy, ~19–33 MB) is dropped once uploaded (`onUpdate`). CPU sampling uses `levels[lv].A/B/C`, which stay. |
| `js/core/resilience.js` (new) | Crash marker, WebGL context-loss card and reload, the recovery toast, `ctx.memEstimate()` |
| `tools/memprobe.mjs` (new) | The measurement above. `--desktop`, `--extra "&safe"`, `--ab` (typed arrays ≥ 128 KB by creating site), `--stop N` |

Safe tiers apply on any device. A desktop that crashed also gets them; that is rare and harmless.

### Crash recovery and context loss (`js/core/resilience.js`)

- The marker (`namba_run` in sessionStorage **and** localStorage, ≤ 20 min old) is written from boot (stage
  `loading` → `title` → `play` → `tutorial_*` → `destination` / `gate` / `phone_*` / `lodestone_*` → `arrived` /
  `endcard`) and refreshed every 10 s with the play time. It is cleared on `pagehide` and when the tab is hidden, so
  only a death **while on screen** leaves it behind.
- A boot that finds it starts in safe tier `prev + 1` (max 2). It logs `[resilience] recovered from …` and shows one
  calm toast when the game is ready: "Restarted in a lighter mode, so Namba fits your phone's memory."
- `webglcontextlost` on the main canvas: `preventDefault`, a full-screen calm card ("Your phone needs a breather ·
  Reloading in a lighter mode — you'll be back in a moment."), the marker with `reason: 'ctxlost'`, and a reload
  after 2.6 s into the next safe tier. We don't attempt an in-place restore: several textures have dropped their
  CPU copies, and a reload is simpler and certain.

## Risks / next levers

- **Emulation can't reproduce jetsam.** The real limit isn't published (roughly 1–1.5 GB for a WebContent process on
  a 6 GB iPhone, and a canvas cap at a quarter of that). We cut about 400 MB, and the biggest bucket, 2D canvases, by
  3×. **Zack: retest on the iPhone.** If it still dies, the next boot will be in safe tier 1, and `namba_recovered`
  tells us where it died.
- **Next levers, if needed:** (1) GeoBatch CPU geometry copies (118 MB of ArrayBuffers) could be released after upload.
  But `npc/places.js _scanSeat` reads shop-interior positions lazily during play, so it needs a guard first; not
  done. (2) The material library's DataTexture data (47 MB) is shared by lazily created clones, so it can't simply
  be dropped. (3) Shop atlas pages keep growing with the world tour (12 pages); a page-count cap with a shared overflow
  page is possible.
- The second WebGL context (Lodestone's stack3d) is kept. It costs 3.5 MB, and iOS allows up to 16 contexts. Making
  it share the main renderer would mean compositing into the DOM phone; that is a lot of risk to save 3.5 MB.
- `resilience.js` treats any on-screen death as a crash, including a force-quit of Safari while the game is
  visible. The cost is one safe-tier boot.
